# 적용 사례 — 업무용 BI 웹 앱(React · Vue 두 구현)

이 문서는 하네스를 실제 제품(React · Vue 두 구현이 같은 API 를 쓰는 BI 웹 앱)에 깔면서 확인한 내용이다. 고객명 · 내부 호스트 · 계정 정보는 넣지 않았다.

## 1. 배경

- 단위 · 종단 시험 601건이 모두 통과한 상태에서 사용자가 하루에 화면 결함 7종을 찾았다.
- 4개월 이력을 모으니 화면 결함은 222건이었고, 기존 자동 시험이 먼저 잡은 것은 18건(8%)이었다.
- 1판(손으로 등록한 진입점 25개 · 불변식 7개)은 222건 중 35건만 대상이었다. 2판에서 전 화면 자동 탐색과 불변식 I9~I27 을 더했다.

## 2. 실사용 결함 → 불변식

## 4. 첫 자동 탐색에서 나온 것(요약)

- 화면 목록: 코드에서 341개(라우트 36 · 관리자 절 12 · 설정 앵커 58 · 매뉴얼 절 154 · BI 단계 · 서랍 8 · 모달 57 · 스튜디오 패널 8 · 라이선스 콘솔 8). 자동 탐색 대상 271.
- 야간 전 화면(R/V 542건, 작업자 2): 23.8분. 화면 커버리지 84%, 요소 커버리지 100%(React 3,921 · Vue 4,066), 클릭 커버리지 77~79%.
- 병합 관문(핵심 화면 7, R/V): 3.2~4.1분.
- 정리 전 첫 야간 실행은 55분 · 위반 1,600여 건이었다. 오탐 정리(아래 §5) 뒤 23.8분 · 수정 대상 위반 약 200건(R↔V 차이 제외)으로 줄었다.
- 처음 나온 위반 묶음: 트리 행 말줄임에 툴팁 없음(5화면) · 프로젝트 카드 ⋯ 메뉴가 Esc 로 안 닫힘 · 인사 연동 규칙 메뉴가 카드 overflow 에 잘림 · 탭 목록 메뉴가 초점을 안 가져감 · 2단계 인증 창을 닫은 뒤 초점이 사라짐 · Vue 내 정보 화면에서 내보내기 작업 목록을 4번 요청 · 테마 미리보기 입력 칸 이름 없음.

## 5. 흔한 오탐과 해결

| 오탐 | 원인 | 해결 |
|---|---|---|
| 원형 아바타 단추 모서리 «가려짐» | 상자 모서리가 원 밖이라 감싸개가 잡힘 | 모서리 inset = 2 + 반지름 × 0.35 |
| 표 행 오른쪽 아래 «가려짐» | 스크롤 막대 위 점은 스크롤 상자가 잡힘 | 보이는 상자를 client 상자로 자른다 |
| 입력 칸 오른쪽 모서리 «가려짐» | 칸 안 증감 단추(복합 컨트롤) | 같은 부모 안 조작 요소의 모서리 덮기는 제외 |
| 본문 건너뛰기 링크 «보이는 넓이 0» | 초점을 받을 때만 나타나는 링크 | 스크롤해도 뷰포트 밖이면 «숨은 요소» 로 센다 |
| 다크 아이콘 단추 «대비 미달» | sr-only 글자(1px 상자)의 색을 읽음 | 1px · clip · clip-path 글자는 대비 대상에서 뺀다 |
| R↔V 상자 위치 199건 차이 | 요소 훑기가 스크롤을 옮긴 뒤 찍음 · 뷰포트 좌표 | 훑기 전에 찍고, 조상 스크롤 양을 더한 문서 좌표로 |
| ⌘K 팔레트 «초점이 표면 밖» | 콤보 상자 규약상 초점은 입력 칸에 남는다 | 입력 칸 또는 목록 안이면 통과 |
| 루트(`/`) 링크 «알 수 없는 경로» | 라우터가 기본 화면으로 넘기는 정상 주소 | 루트를 라우트 패턴에 넣는다 |
| 전환 깜빡임 측정이 결함을 놓침 | 빈 화면으로 «안정» 된 로딩 중에 측정을 멈춤 | 처음 면적의 절반 이상으로 돌아올 때까지 본다 |

## 6. 운영에서 배운 것

- **클릭 탐색이 시험 DB 를 바꿨다.** 내 정보 화면의 «패널 배치» 선택 단추를 눌러 소유자 계정이 도킹 배치로 바뀌었고, 그 뒤 다른 시험의 모달이 열리지 않았다. 토글(aria-pressed · aria-checked) · 선택 묶음(radiogroup · 세그먼트) · 증감 단추 · 색 견본을 클릭 대상에서 빼고, 화면마다 개인 설정 · 워크스페이스 설정을 앞뒤로 비교해 바뀌면 «MUTATION» 으로 기록하고 개인 설정은 되돌리게 했다.
- **부하.** 다른 작업의 전체 시험과 겹치자 1분 부하가 260 까지 올랐다. 야간 순회를 멈추고 «결과 파일이 있는 화면 건너뛰기» 로 이어 돌렸다.
- **번호 충돌.** 다른 작업이 같은 원장 번호(케이스 ID)를 먼저 썼다. 병합 전에 통합 브랜치와 상대 작업 브랜치의 원장 번호를 확인한다.
