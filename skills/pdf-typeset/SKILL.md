# PDF 조판 — 공통 방법과 지침

## 0. 먼저 — 이 프로젝트에 조판기가 있는지 찾는다

새로 짜기 전에 프로젝트 안의 조판기를 찾는다. 있으면 그것을 쓰고, 고칠 곳만 고친다.

```bash
rg -a -l 'printToPDF|page\.pdf\(|pdf-lib|generateDocumentOutline|pdfunite' -g '!node_modules' .
```

- 프로젝트 설정 파일(`.claude/skills-config/pdf-typeset.md`)이 있으면 **먼저 읽는다**(그 저장소의 빌더 지도 · 명령 · 검사 · 보관 규칙).
- 다이어그램을 그리거나 고치면 → **`reference/diagrams.md` 를 읽는다**(도구 고르기 · 공통 테마 · 배치 · 품질 점검표).
- 설계 산출물 · 개발 문서 세트의 구성 · 생성 장 · 요구사항 추적 · 현행화 · 문서 정리 규칙은 → **`design-deliverables` 스킬**을 쓴다. 이 스킬은 PDF 를 굽는 방법만 다룬다.
- 조판기가 없으면 아래 1~4 절의 방법으로 새로 만들고, 9 절 점검표로 확인한다. 바로 쓸 수 있는 도우미는 `scripts/` 에 있다.

| 도우미 | 하는 일 | 의존 |
|---|---|---|
| `scripts/print-pdf.mjs <html> <pdf> [--wait-expr 식]` | 헤드리스 Chrome 으로 HTML 을 PDF 로 굽는다(책갈피 · 차례 링크는 Chrome 이 쓴다) | Node 22 이상, Chrome |
| `scripts/pdf-nav.mjs <pdf> [--labels …] [--nav nav.json]` | 열 때 책갈피 창 · 쪽 번호 표기 · (합본일 때) 책갈피 트리와 차례 링크를 다시 단다 | 프로젝트의 `pdf-lib` |
| `scripts/check-pdf.py <pdf>…` | 쪽 · 가로 쪽 · 책갈피 단계별 수 · 내부 링크 수 · 책갈피 창 · Type 3 글꼴 · 크기를 센다. 기준 미달이면 exit 1 | `pypdf` |

## 1. 조판 흐름

1. **원고** = Markdown(또는 원고 객체). 제목 단계는 장(`##`) → 절(`###`) → 소제목(`####`) 세 단계만 쓴다. 장 · 절 번호는 조판할 때 붙인다.
2. **HTML** = 자체완결 한 파일. 글꼴 · 그림 · CSS · 조판 스크립트를 모두 안에 넣는다(외부 요청 0 — 폐쇄망에서도 같은 결과). 그림은 data URI, SVG 는 문서에 그대로 넣는다(`<img>` 로 넣으면 내장 글꼴이 SVG 안에 닿지 않는다).
3. **쪽 나누기** = 문서 안 조판 스크립트가 블록을 재어 쪽(`.page`)에 배분하고, 끝나면 창 변수(예: `window.__paged = true`)를 세운다. 쪽 크기는 CSS `@page` 가 정한다. 간단한 문서는 CSS `break-before` 만으로도 된다.
4. **PDF** = 헤드리스 Chrome CDP `Page.printToPDF`:
   `printBackground: true · preferCSSPageSize: true · 여백 0 · displayHeaderFooter: false · generateDocumentOutline: true · transferMode: 'ReturnAsStream'`.
   - 책갈피는 제목 요소(h1 · h2, 또는 `role=heading` + `aria-level` 1 · 2)에서 장 › 절 두 단계로 생긴다. 책갈피에 들어갈 제목 요소는 장 · 절 두 단계만 둔다(다른 제목 요소는 `div` 로).
   - 차례 줄의 `<a href="#앵커">` 는 그대로 PDF 내부 링크가 된다.
   - 결과는 스트림(`IO.read`)으로 받는다. 수 MB 를 한 번에 받으면 응답이 오지 않을 수 있다.
   - Playwright 를 쓰면 `page.pdf({ preferCSSPageSize: true, printBackground: true, outline: true, tagged: true })`(1.42 이상)가 같은 일을 한다.
5. **후처리**(pdf-lib) = `/PageMode /UseOutlines`(열 때 책갈피 창) + `/PageLabels`(뷰어 쪽 번호 칸 = 종이에 찍힌 번호. 표지 · 앞붙임 i, ii · 본문 1, 2). 여러 PDF 를 합치면(`pdfunite`) 문서 사이 링크와 책갈피가 사라지므로, 합본의 차례 쪽 글자 위치(`pdftotext -bbox`)를 읽어 책갈피 트리와 링크를 새로 단다. 후처리는 다시 돌려도 결과가 같아야 한다.

## 2. 모든 PDF 의 필수 요소

- **차례 + 차례 링크 + 책갈피(장 > 절) + 열 때 책갈피 창.** 쪽이 몇 장 안 되는 브로셔도 책갈피는 단다.
- **표지**: 문서 번호 · 제목 · 적용 버전 · 발행처 · 배포 등급. 사내 문서는 배포 등급(예: 「대외비 · 사내 보관」)을 표지와 문서 정보에 적는다.
- **문서 정보**: 개정 이력(버전 · 날짜 · 내용 · 작성) · 대상 독자 · 관련 문서.
- **머리글 · 바닥글**: 권 제목, 장 › 절, 쪽 번호. 앞붙임은 로마 숫자(i, ii, iii, iv …)로 찍는다.

## 3. 그림 · 표 · 목록 배치

**그림마다 배율을 맞춘다.** 한 배율로 모든 그림을 줄이지 않는다.
- 기본 배율을 정하고(예: 0.8), 실린 뒤 가장 작은 글자가 하한(예: 9px) 밑이면 그 그림만 하한이 되는 배율까지 키운다.
- 키운 그림을 넣을 자리를 차례로 고른다: 본문 안 → 한 쪽 전체(세로) → **그 쪽만 A4 가로**. 폭이 넘치는 그림은 가로 쪽으로 간다.
- 어느 자리에도 하한으로 들어가지 않으면 원본을 의미 단위로 **나눈다**(그림 3-6a · 3-6b, 캡션 끝 「(1/2)」).
- 가로 쪽은 그 블록에만 표시(`data-land="1"`)하고 CSS 로 크기를 따로 준다:
  ```css
  @page land { size: 297mm 210mm; margin: 0 }
  .page.land { page: land; width: 297mm; height: 210mm }
  ```
  가로 쪽 다음 본문은 새 세로 쪽에서 잇는다. 가로 쪽 그림이 이어지면 자리가 남는 만큼 같은 가로 쪽에 함께 싣는다.

**표.**
- 열 폭은 내용 길이에 비례해 나눈다. 셀 글자는 `word-break: keep-all; overflow-wrap: anywhere` 로 한글 낱말을 지키며 줄을 바꾼다.
- 표가 쪽에 다 들어가지 않으면, 남은 자리에 머리글 + 최소 행 수(예: 3행)가 들어갈 때 쪼개 채우고 머리글을 다음 조각에 반복한다. 표를 통째로 다음 쪽으로 넘겨 쪽 아래를 비우지 않는다.
- 열이 많은 표(예: 역할 열 6개 이상 또는 전체 열 8개 이상)는 그 쪽만 가로로 싣는 것이 원칙이다. 조판기가 표 가로 쪽을 지원하는지 먼저 코드로 확인한다(그림만 지원하는 조판기가 많다). 프로젝트 설정 파일에 표 가로 쪽 지원 여부가 적혀 있으면 그것을 따른다.

**긴 목록은 엑셀로 뺀다.** 수백~수만 행 목록(시험 케이스 전체 · 색인 정의 · 모듈 목록 · 클래스 목록)은 본문에 요약과 대표 행만 두고, 전체는 같은 이름의 `.xlsx` 로 만든 뒤 본문에서 「엑셀 `<파일>` 의 「<시트>」 시트」로 가리킨다. 절이 아주 많은 장(예: 20개 초과)은 장 표지에 절 목록을 싣지 않고 개수만 알린다.

**넘침 0.** 조판 스크립트는 쪽 영역을 넘친 쪽 번호를 모아 알리고(예: `window.__overflow`), 빌더는 넘친 쪽이 있으면 경고를 낸다. 출하 전에는 넘친 쪽 0 이어야 한다.

## 4. 글꼴 · 크기 · 캡처

- **한글 글꼴을 내장한다.** 저장소에 Noto Sans KR(가변 woff2, 또는 Regular · Bold TTF)을 두고 base64 `@font-face` 로 넣는다. 코드 글꼴(JetBrains Mono 등)도 같다. 글꼴 사용권(SIL OFL 1.1)은 `OFL.txt` 를 글꼴 옆에 두고, 제3자 고지 문서에 올린다.
- 시스템 글꼴(예: Apple SD Gothic Neo)에 기대면 Chrome 이 PDF 에 Type 3 글꼴로 넣는다. 그러면 파일이 커지고 글자 검색 · 복사가 깨진다(`check-pdf.py` 가 경고한다).
- **PDF 크기**: 글자에 `stroke` 로 테두리를 두르면 Chrome 이 글리프를 곡선(Type 3)으로 넣어 쪽마다 글꼴이 수십 개 생긴다. 글자 뒤 바탕색 테두리가 필요하면 stroke 대신 바탕색 채움 글자 사본을 몇 개 어긋나게 겹친다. 사진은 JPEG/WebP 로 줄여 넣는다.
- **화면 캡처는 2x** 로 찍는다: Chrome `--force-device-scale-factor=2`, Playwright `deviceScaleFactor: 2`. 1x 캡처는 글자가 뭉개진다. 자세한 방법은 `retina-capture` 스킬. PDF 를 굽는 Chrome 자체는 배율 1 이면 된다(글자 · SVG 는 벡터로 들어간다).

## 5. 문장 · 표기 지침

- 문체: 산출물 · 개발 문서는 「~한다」 평서체. 매뉴얼 · 안내서는 그 문서가 이미 쓰는 문체를 따른다. 근거 원칙은 `readable-korean` 스킬의 `reference/report-writing-rules.md`.
- **개발 과정의 흔적을 남기지 않는다**: 작업자 · 작업 묶음 · 대화 이름(오너 · 레인 · 웨이브 · 세션 등), 에이전트 지침 파일(CLAUDE.md · AGENTS.md)을 근거로 드는 문장, 「분석해 보겠습니다」 같은 과정 설명, TODO. 「오너 결정」은 「결정」으로 쓴다.
- **「미확인」을 쓰지 않는다.** 소스 · 설정 · 실측으로 확인해 채운다. 정말 정할 수 없는 값(실측 전 · 외부 정보 · 내리지 않은 결정)은 `> **예정**: <언제 · 어디서 채우는지>` 로 쓴다.
- 버전을 뜻하는 말은 「판」이 아니라 「버전」이다(개정판 · 수정판 · 이 판 → 버전). 프로젝트에 용어 사전이 있으면 그 검사를 돌린다.
- 숫자 · 목록은 세어서 쓴다. 다른 문서의 값을 베끼지 않는다.
- 잘 읽히는 한국어 네 규칙 — 연결어를 빼지 않는다 · 사물을 사람처럼 쓰지 않는다 · 명사를 셋 이상 조사 없이 잇지 않는다 · 주어와 서술어를 멀리 띄우지 않는다. 마감 전에 `readable-korean` 스킬로 점검한다.

## 6. 결과 PDF 검증

```bash
# <스킬 폴더> = 이 스킬을 불러올 때 표시되는 기본 디렉터리(Base directory)
python3 <스킬 폴더>/scripts/check-pdf.py out/*.pdf --min-outline 2 --min-links 2
pdftotext -layout out/x.pdf - | less     # 차례 쪽 번호가 본문과 맞는지 눈으로
```

확인할 것:
- 책갈피 수 = 차례 줄 수(장 + 절), 단계는 장 › 절 두 단계, 내부 링크 수 ≥ 차례 줄 수.
- 차례 쪽 번호가 커지는 순서이고, 링크가 차례에 적힌 쪽으로 간다(뷰어 쪽 번호 표기 기준).
- 열 때 책갈피 창 켬, 넘친 쪽 0, Type 3 글꼴 없음, 가로 쪽 수가 의도와 같음.
- 쪽 이미지를 2x 로 몇 장 뽑아(`pdftoppm -r 144 -png -f N -l N`) 그림 글자 크기 · 표 잘림을 눈으로 본다.

## 7. 운영 주의

- **부하**: 큰 문서 세트 전체 재조판은 무겁다(실측 예: 42권 약 5분 · 6,786쪽 · 310MB). `uptime` 1분 평균이 20 아래일 때 한 번에 하나만 돌린다. 시험 · 다른 빌드와 겹쳐 돌리지 않는다.
- **헤드리스만**: `--headless=new`. 창을 띄우지 않는다(사용 중인 화면의 포커스를 빼앗는다).
- **띄운 Chrome 은 PID 로 끈다**: 빌더가 `spawn` 한 프로세스를 `proc.kill()` 로 끄고 임시 프로필을 지운다. `pkill -f Chrome` 같은 패턴 종료는 다른 Chrome 까지 끄므로 쓰지 않는다. 남은 프로세스는 `pgrep -fl <임시 프로필 이름>` 으로 찾아 그 PID 만 끈다.
- 조판기 시간 상한은 문서 크기에 비례해 잡는다. 고정 60초면 큰 권에서 대기가 조판보다 먼저 끝난다.

## 8. 보관 규칙(일반 원칙 — 프로젝트 규칙이 있으면 그것을 따른다)

- 완성 PDF 는 버전마다 다시 조판해 커밋한다. 중간 산출물(그림 SVG · 조판 HTML)은 `.gitignore` 로 빼고 커밋하지 않는다.
- 생성물(`*.gen.md` 등)은 손으로 고치지 않는다. 생성기를 고쳐 다시 만든다.
- 산출물을 `~/Downloads` 에 두지 않는다. 저장소 안 정해진 출력 자리에 둔다.

## 9. 새 PDF 빌더를 만들 때 점검표

- [ ] 프로젝트에 이미 있는 조판기 · 후처리를 재사용했는가(0 절 검색 결과)
- [ ] HTML 이 자체완결인가(글꼴 · 그림 · 스크립트 인라인, 외부 요청 0)
- [ ] 한글 글꼴을 내장했고 글꼴 사용권 고지를 올렸는가
- [ ] 표지 · 문서 정보 · 차례 · 머리글 · 바닥글 · 쪽 번호(앞붙임 로마 숫자)가 있는가
- [ ] `generateDocumentOutline`(또는 `outline: true`)과 차례 앵커 링크를 켰는가, 합본이면 책갈피 · 링크를 다시 다는가
- [ ] `/PageMode /UseOutlines` 와 `/PageLabels` 를 붙였는가
- [ ] 그림마다 배율을 맞추고, 넓은 그림(필요하면 표)은 그 쪽만 가로로 싣는가
- [ ] 표 쪼개기 · 머리글 반복, 긴 목록 엑셀 분리, 넘친 쪽 검사가 있는가
- [ ] 헤드리스 · PID 종료 · 임시 프로필 삭제 · 시간 상한이 있는가
- [ ] 결과를 `check-pdf.py` 로 세고, 쪽 이미지를 2x 로 몇 장 눈으로 봤는가
- [ ] 차례 · 책갈피 · 링크를 지키는 자동 시험이 있는가(커밋된 PDF 를 다시 읽어 확인)
- [ ] 문장이 5 절 지침을 지키는가(`readable-korean` 점검)
