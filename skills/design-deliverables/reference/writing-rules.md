# 문서 규칙 — 쓸 때 점검표 · 정리 절차 · 카운트 명령

문장의 정본은 `readable-korean` 스킬의 `reference/report-writing-rules.md` 다(이 파일에 옮겨 적지 않는다). 아래는 제품 책임자 결정으로 굳어진 상시 규칙을 산출물 · 개발 문서 · 매뉴얼에 맞게 모은 것이다.

## 1. 쓸 때 점검표

**내용**
- [ ] 숫자 · 목록(도구 수 · 라우트 수 · 역할 · 커넥터 · 한도)을 코드에서 세어 썼다. 다른 문서 값을 베끼지 않았다
- [ ] 「미확인」 · 「확인하지 못했다」를 쓰지 않았다. 소스 · 설정 · 마이그레이션 · 시험 · git 이력으로 채웠다. 정말 소스로 정할 수 없는 값(실행 중 측정값 · 외부 기관 · 고객 정보 · 내리지 않은 결정)만 `> **예정**: <언제 · 어디서 채우는지>` 로 썼다
- [ ] 아직 구현하지 않은 기능을 구현된 것처럼 쓰지 않았다(「계획 기능」 절)
- [ ] 사실을 한 권에 한 번만 썼고, 다른 권 사실은 참조로 이었다

**개발 과정의 흔적 금지**
- [ ] 에이전트 지침 · 작업 파일(`CLAUDE.md` · `AGENTS.md` · `progress.md` · `.claude/` · `.omc/`)을 근거나 정본으로 들지 않았다. 정본은 실제 문서 · 소스 파일로 적었다
- [ ] 개발 도구 · 모델 이름(Claude · Claude Code · codegraph · superpowers · 모델 이름 등)을 작성자 · 근거로 쓰지 않았다
- [ ] 작업 방식 낱말(서브에이전트 · 실행자 · 검증자 · 오케스트레이션 · 레인 · 레인키퍼 · 웨이브 · 세션 · 핸드오프 · 프롬프트 · 「에이전트가 작성/설계/검수」 · 「AI 가 생성」 · 개발용 하네스)이 없다
- [ ] 작업 폴더 이름 · 임시 경로(`wt-*` · 개인 작업 폴더 · `.claude-scratch` · `/private/tmp`)가 없다
- [ ] 「오너 지시」 · 「오너 결정」을 「결정」으로 썼다(날짜 · 근거 문서는 남긴다)
- [ ] **지우면 안 되는 것**: 제품의 AI 어시스턴트 · 에이전트 연결 · MCP 도구처럼 고객이 쓰는 기능 설명은 그대로 둔다. 시험 도구 경로는 경로로 남기되 설명은 「시험 실행 환경」 같은 업무 말로 쓴다

**표기**
- [ ] 버전을 뜻하는 말은 「버전」 하나로 썼다(「판」 · 「버젼」 쓰지 않음). 용어 사전이 있으면 검사로 강제한다
- [ ] 업계 외래어 원칙: 버튼 · 패널 · 셀 · 필드 · 뷰 · 내보내기 · 샘플 · 게시 · 드래그 앤 드롭 · 헤더 · 페이지 · 예약 발송 · 툴바. 「적재」는 그대로 둔다
- [ ] 산출물 · 개발 문서는 「~한다」 평서체, 매뉴얼은 그 문서가 쓰는 문체(예: 해요체를 쓰는 인앱 매뉴얼은 해요체)
- [ ] 매뉴얼 문구는 긴 문단 대신 짧은 목록, 한 줄에 한 사실(40자 안팎)
- [ ] 화면 문구는 짧은 사람 말, 약어 · 질문형 제목 · 장식 설명 없이
- [ ] 과장 · 비유 · 개발자 방언 · AI 투 표현이 없다(정본 §2 · §4 · §5)
- [ ] 잘 읽히는 한국어 네 규칙(연결어 생략 · 사물 의인화 · 명사 셋 이상 잇기 · 짝 말 멀리 띄우기)을 `readable-korean` 스킬로 점검했다. 통과하지 못한 원고는 미완료다

**모양 · 결과물**
- [ ] 모든 PDF 에 차례 · 차례 링크 · 책갈피(장 > 절) · 열 때 책갈피 창이 있다(`pdf-typeset`)
- [ ] 열 많은 표는 그 쪽만 가로, 그림은 그림마다 배율을 맞췄고 해상도를 낮추지 않았다
- [ ] 수백 행 목록은 엑셀로 뺐다. 통합본은 원본 품질 그대로다
- [ ] 시험 결과는 엑셀로 저장해 저장소에 남겼다
- [ ] 캡처는 2x 헤드리스로 찍었다
- [ ] 화면 시안 · 견본은 실제 토큰 CSS 와 공용 클래스로 만들었다. 카드 · 알림 · 패널 가장자리에 색 띠를 두지 않았고, 제품 UI 에 이모지를 쓰지 않았다
- [ ] 화면 구조를 바꾸는 시안은 구현 전에 보여 주고 확인받았다
- [ ] 끝난 작업은 캡처 · 전후 비교 · 수치를 담은 아티팩트로 보고했다. 다시 볼 아티팩트 HTML 과 근거 문서는 저장소(예: `docs/reports/artifacts/`)에 저장한다
- [ ] 산출물을 개인 다운로드 폴더에 두지 않았다. 브로셔처럼 버전마다 새로 만드는 결과물은 이전 버전 파일을 남겼다
- [ ] 교육용 책은 업무 문서와 장르가 다르다. 서사 문단과 인쇄 출판물 수준 조판을 쓰고, 사실 · 숫자 정확성과 AI 투 금지는 유지한다

## 2. 정리할 때 절차

이미 쓴 문서 묶음에서 위 규칙 위반을 걷어 낼 때 쓴다. **기계적 일괄 치환은 하지 않는다.**

1. **카운트**: 아래 명령으로 대상 폴더의 건수를 파일별로 잰다. 결과를 보고에 「전」으로 남긴다.
2. **소스 확인**: 「미확인」 줄마다 실제 값을 소스 · 설정 · 마이그레이션 · 시험 · git 이력에서 찾는다(코드 탐색은 codegraph 먼저, 문자열은 `rg -a`). 찾으면 문장을 사실로 바꾼다. 소스로 정할 수 없는 것만 `> **예정**:` 으로 바꾸고, 보고의 「소스로 못 채운 항목」 표에 파일 · 줄 · 이유를 적는다. 업무상 정상 표현(「확인」 버튼 · 확인 대화상자 · 사용자가 확인한다)은 건드리지 않는다.
3. **교체**: 개발 흔적 문장은 업무 문장으로 바꾸거나 지운다. 지운 파일을 가리키는 링크는 실제 정본 문서로 바꾼다. 「판」은 문맥으로 하나씩 판단해 「버전」으로 바꾸고 조사를 맞춘다(판을 → 버전을).
4. **재생성**: 바뀐 문장이 생성 장에 있으면 생성물을 고치지 말고 생성기 · 원천 · 표기 변환 함수를 고친 뒤 다시 만든다.
5. **검사**: 같은 카운트를 다시 재서 「후」로 남기고, 산출물 검사 · 문서 검사 · 용어 사전 검사를 돌린다. 일부러 남긴 사례는 이유와 함께 보고한다.

## 3. 카운트 명령

```bash
DIR=docs   # 대상 폴더
# 1) 미확인 · 확인 못함
rg -a -c '미확인|확인(하|되)?지 (못|않)' "$DIR"
# 2) 개발 흔적
rg -a -c 'CLAUDE\.md|AGENTS\.md|progress\.md|서브에이전트|레인키퍼|Claude|codegraph|오케스트|\.claude-scratch|wt-next|오너' "$DIR"
rg -a -c -e '(^|[^가-힣])(레인|웨이브|세션|핸드오프|실행자|검증자)([^가-힣]|이|을|은|의|에|별|마다)' "$DIR"   # 결과는 문맥으로 걸러 본다
# 3) 버전 뜻 「판」 후보와 남은 낱말 종류
rg -a -c -e '(^|[^가-힣])판(이|을|은|의|에|마다|으로|별| 올림)?([^가-힣]|$)' "$DIR"
rg -a -o -N -e '[가-힣]*판[가-힣]*' "$DIR" | sort | uniq -c | sort -rn | head -40
# 4) 예정 표기 수(줄어드는지 본다)
rg -a -c '> \*\*예정\*\*' "$DIR"
```

「판」 낱말 종류 결과에서 바꾸지 말아야 할 것: 판단 · 판정 · 판매 · 판별(구별 뜻) · 출판 · 조판 · 판형 · 평판 · 간판 · 판권 · 판례 · 게시판 · 자판. 바꿀 것의 예: 1.12판 · 판 올림 · 판마다 · 이번 판 · 다음 판 · 판별(버전별 뜻) · 검토판 · 완성판 · 웹판 · PDF판 · 개정판 · 새 판.

「세션」 · 「에이전트」는 제품 기능(로그인 세션 · 에이전트 연결)으로도 쓰이므로 결과를 문맥으로 걸러 낸다.
