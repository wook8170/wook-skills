# 문서 현행화 절차

문서와 제품이 다른 것은 GS 인증의 주요 반려 사유다. 산출물이 개발 절차에 묶여 있지 않으면 아무도 모르게 낡는다. 그래서 **기능 변경마다** 맞추고, **버전 출하 때** 한 번 더 전 권을 맞춘다.

## 1. 기능 변경 때(같은 변경 안에서)

1. **요구사항 ID 를 정한다.** 바뀌는 기능이 어느 요구사항에 속하는지 요구사항 원천에서 찾는다. 없으면 새 기능은 기능 원장에 행을, 그 밖 요구는 요구사항 원천 데이터에 다음 번호로 더한다. 커밋 메시지 · PR 본문에 ID 를 적고, 무관하면 「요구사항 해당 없음」이라고 적는다.
2. **크로스체크 대상을 대조한다.** 프로젝트 규칙에 적힌 목록을 따른다. 기준 저장소는 아래 6종을 대조한다.

   | # | 대상 | 볼 것 |
   |---|---|---|
   | 1 | 개발 문서(도메인 문서 + 문서 대장) | 8축(컨셉 · 아키텍처 · 구조 · 인터페이스 · 제약 · 규격 · 오픈소스 · 커스터마이징). 인터페이스와 제약은 매번 확인하고, 한도 수치는 코드 상수를 `파일:줄` 로 인용 |
   | 2 | 인앱 사용자 매뉴얼 | 두 프런트엔드 동일 내용, 정확한 화면 문구, 스크린샷 재촬영 |
   | 3 | 경쟁력 백로그 | 상태(완료 · 완료(부분) · 미착수)와 근거 파일. 문서가 정본, 상수는 사본. 부분 구현을 완료로 올리지 않는다 |
   | 4 | 제품 소개 페이지 | 기능 목록 · 수치 · 구성 표기 |
   | 5 | 브로셔 | 원고는 같은 변경에서, PDF 는 버전 올림 때 새 파일(이전 버전 파일은 지우지 않는다) |
   | 6 | 설계 산출물 | 아래 3 · 4 |

3. **영향 권을 찾는다.** 색인의 근거 소스 역색인으로 「바뀐 파일 → 권 · 장」을 찾는다. 바뀐 파일을 근거로 쓰는 **생성 장은 필수**, **손으로 쓴 장은 검토** 대상이다. 기준 저장소에서는 문서 동기화 명령이 이 판정을 내고, 손으로 쓴 장은 그 명령의 `drafts` 모드가 바뀐 소스를 적은 문단을 줄 번호로 보여 준다.
4. **생성물을 다시 만들고 끊김을 검사한다.** 원천 데이터 → 생성 장 → 엑셀 → 색인 순으로 영향 권만 다시 만든다. 요구사항 원천이 바뀌면 요구사항 · 기능 명세 · 추적표 권의 생성 장과 추적 데이터가 필수다. 마지막에 산출물 검사(재생성 비교 · 추적 래칫 · 정합 오류 0)를 통과시킨다.
5. 손으로 쓴 장을 고쳤으면 `writing-rules.md` 점검표와 `readable-korean` 스킬로 점검한다.

시험도 같은 변경에서 맞춘다. 기능 추가는 단위 시험 + (사용자 여정이 생기면) e2e 정상 · 권한 거부 · 대표 오류, 수정은 기대값 · 회귀 시험, 삭제는 해당 시험 삭제 또는 대체다. 시험 케이스 원장(예: `docs/e2e/<모듈>.cases.json` → 엑셀)이 있으면 함께 다시 만든다.

## 2. 버전 출하 때

1. 정합 검사가 보여 주는 「권마다 `syncedCommit` 이후 바뀐 근거 소스」 목록이 손 서술 현행화 대상이다. 근거를 다시 읽고 내용을 맞춘 장만 처리한다.
2. 권 메타의 `edition` · `syncedCommit`(출하 태그 커밋 기준) · `revisions` 를 올린다. 근거를 읽지 않고 `syncedCommit` 만 옮기지 않는다.
3. 캡처(스토리보드 · 공통 UI · 상태 화면 · 매뉴얼 그림)를 통합 검증 뒤 한 번 다시 찍는다.
4. 전 권을 다시 조판하고(`pdf-typeset`), 권별 엑셀을 다시 만든 뒤 통합본(PDF · 엑셀)을 다시 만든다.
5. 완성 PDF · 엑셀 · 통합본은 저장소에 커밋하지 않는다. 개발 머신에서 조판한 버전 묶음을 서명해 산출물 보관 서버(기준 저장소는 라이선스 관리 서버의 설계 산출물 메뉴)에 버전마다 올린다(2026-11-11 결정 — 이전의 「버전마다 커밋」 결정을 대체). 보관 서버가 없는 프로젝트는 버전 묶음을 릴리스 첨부 등 저장소 밖 보관소에 둔다. 중간 산출물(그림 SVG · 조판 HTML · 다시 만들 수 있는 견본 그림)은 커밋하지 않는다.
6. 버전 올림 고정 목록도 함께 본다: 변경 기록 · 업그레이드 안내 · 릴리스 노트 · 고객 문서 재조판 · 브로셔 새 파일 · README · 매뉴얼 재촬영 · 제품 소개 수치 · 기능 목록 문서 머리말 기준일 · 백서 · 품질 보고서 · 외부 도구 표면(MCP 도구 · CLI) 대조 · 개발자 문서 생성 데이터.

## 3. 판단이 필요한 경우

- 연결(요구사항 → 화면 → 시험)을 채울 수 없으면 래칫 기준선을 올리지 않고 결정권자 확인을 받는다.
- 문서에 옛 문구를 일부러 남겨야 하면(이력 서술 등) 확인 기록 파일에 근거를 남긴다(기준 저장소는 `scripts/docs-sync/acks.json`).
- 자동 생성 문서는 손으로 고치지 않고 생성 명령으로 다시 만든다.
