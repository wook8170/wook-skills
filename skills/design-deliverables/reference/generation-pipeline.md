# 원천 → 생성 장 → 조판 흐름과 검사

## 1. 흐름

```
코드 · 설정 · 마이그레이션 · OpenAPI · 라우터 · 기능 원장 CSV
   │  (+ 권 폴더 data/*.json 원천 데이터 — 코드로 못 뽑는 것만, 행마다 근거)
   ▼
원천 데이터 생성기(data/*.gen.json)  ─┐
   ▼                                  │
생성 장(*.gen.md) · 생성 그림(*.gen.mmd) · 엑셀(xlsx/) · 색인(INDEX.md · index.json)
   ▼                                  │
사람이 쓴 장(*.md) + 생성 장  ──→  조판(HTML → PDF, pdf-typeset)  ──→  권별 PDF  ──→  통합본 PDF · 엑셀
```

순서가 중요하다. 기준 저장소에서 한 권을 고친 뒤의 순서: 원천 데이터 → 생성 장 → 엑셀 → 색인 → 그림 → 조판 → 검사.

## 2. 생성 장과 사람이 쓰는 장의 경계

| 생성(손으로 쓰지 않음) | 사람이 씀 |
|---|---|
| 테이블 정의 · API 전수 · 도구 · CLI 명령 전수 · 화면 라우트 전수 · 마이그레이션 목록 · 환경 변수 · 기능 · 요구사항 전수 · 권한 매트릭스 칸 값 · CRUD · 인덱스 · 실행 계획 · 흐름 시퀀스 뼈대 · ERD | 설계 이유 · 제약 · 흐름 해설 · 설계 결정 · 정책 문장 · 업무 흐름도 · 화면 항목 설명 |

- 생성 장 파일 이름은 `NN-<이름>.gen.md`. 권 메타 장 항목에 `generator` 와 `options` 를 적으면 생성기가 그 장을 만든다.
- 생성 장 머리 두 줄:
  ```
  <!-- sources: … -->
  <!-- generated: gen-chapters.mjs · generator=tables · target=테이블 · total=140 · covered=140 · sha256=… -->
  ```
  `sha256` 은 머리 아래 본문의 해시다. 본문을 손으로 고치면 해시가 맞지 않아 검사기가 잡는다.
- 생성 그림(`*.gen.mmd`)도 손으로 고치지 않는다. 손으로 다듬은 그림이 필요하면 `.gen` 이 없는 이름으로 따로 만든다.
- 생성 장은 원천 문구(OpenAPI 설명 등)를 옮기므로 어미 검사에서 뺀다.
- 결과에 날짜 · 시각을 넣지 않는다. 그래야 같은 입력에서 같은 결과가 나오고, 재생성 비교가 성립한다.

## 3. 표기 변환(코드 주석 → 문서 표기)

코드 주석을 문서로 옮길 때는 변환 함수 하나(기준 저장소의 `scripts/deliverables/gen/doc-text.mjs` 의 `docText`)를 거친다. 원본 파일(마이그레이션 SQL 등)은 고치지 않는다. 적용 이력 검사 대상이라 주석만 바꿔도 다른 파일이 되기 때문이다.

- 「PostgreSQL 판」 · 「SQLite 판」처럼 방언별 파일을 뜻하는 「판」 → 「… 용」
- 제품 버전을 뜻하는 「판」 → 「버전」(「2판」 → 「버전 2」). 판단 · 판정 · 조판처럼 다른 낱말 안의 「판」은 그대로 둔다. 「판별」은 뜻이 겹쳐 바꾸지 않는다.
- 「오너 결정 · 지시 · 확인 …」 → 「오너」를 뺀 낱말

변환 규칙에는 단위 시험(`doc-text.test.mjs`)을 붙인다.

## 4. 엑셀

- 엑셀은 손으로 만들지 않는다. 권마다 생성기 `xlsx/gs_dd_<nn>.py` 가 `workbooks(root) -> { 파일 이름: [시트, …] }` 를 돌려주고, 공용 빌더(`build-xlsx.py`)가 서식(머리글 굵게 · 채움 · 줄바꿈 · 열 너비)을 입혀 저장한다.
- 시트 모양: `{ 'name', 'columns': [(머리글, 너비)], 'rows': [[…]] }`. 파일 이름은 권 메타 `xlsx[].file` 과 같아야 한다.
- 수백 행이 넘는 목록은 본문에 요약과 대표 행만 두고 「엑셀 `<파일>` 의 「<시트>」 시트」로 가리킨다(사례: 시험 케이스 전체를 엑셀 6시트로 빼서 본문 1,315면 → 40면).

## 5. 색인

`build-index.mjs` 가 권 대장 · 권 메타 · 장 파일을 읽어 `INDEX.md` · `index.json` 을 만든다. 내용은 권 목록 · 권별 목차 · 엑셀 목록 · **근거 소스 역색인**(파일 하나가 어느 권 · 장에 쓰였는지)이다. 역색인은 현행화 때 「바뀐 파일 → 고칠 장」을 찾는 데 쓴다. `--check` 는 드리프트만 확인한다.

## 6. 통합본

- 권별 PDF 와 권별 엑셀을 먼저 만든 뒤 묶는다. 그래서 통합본은 언제나 그 버전의 권별 결과물과 같은 내용이다.
- PDF 통합본: 통합 표지 → 문서 정보 → 통합 차례(분류 > 권 > 장) → 권을 분류 순서로 이어 붙인다. 권마다 표지 · 문서 정보 · 차례를 그대로 둔다.
  - 책갈피는 분류 > 권 > 장 > 절 네 단계, 열 때 책갈피 창, 쪽 번호 표기는 통합 쪽 기준.
  - 권 안의 차례 링크는 이름표가 겹치므로 통합 쪽을 직접 가리키는 링크로 바꿔 단다.
  - 차례 쪽 수가 정해져야 권 시작 쪽이 정해지므로, 쪽 수가 맞을 때까지 앞붙임을 다시 굽는다(보통 두 번).
  - 내용이 같은 스트림 · 글꼴 사전만 합친다. **그림을 다시 압축하거나 해상도를 낮추지 않는다**(통합본은 원본 품질).
  - 권을 하나씩 읽어 복사하고 버린다. 메모리에는 통합본과 권 하나만 올린다.
- 엑셀 통합본: 「목차」 시트 → 권별 시트(`DD<권 번호>-<원래 시트 이름>`, 31자에서 자르고 겹치면 `~2`) → 「통합본 정보」 시트. 값 · 수식 · 서식 · 열 너비 · 틀 고정 · 자동 필터 · 병합 셀 · 하이퍼링크를 옮긴다. 옮기지 못하는 요소(데이터 유효성 · 조건부 서식 · 그림 · 차트 · 메모)는 경고로 알린다.

## 7. 산출물 검사(한 명령으로 묶는다)

기준 저장소의 `deliverables:check` 구성이다. 저장소 전체 관문(`gate`)의 한 단계로 넣는다.

| 단계 | 보는 것 | 실패하면 |
|---|---|---|
| 앞선 단위 시험 | 래칫 · 그림 · 표기 변환 · 통합본 · 견본 · PNG 크기 · 엑셀 통합 · 화면 항목 추출기 | 해당 스크립트를 고친다 |
| ① 생성 장 재생성 비교 | 생성 장 · 생성 그림을 메모리에서 다시 만들어 커밋된 파일과 글자 단위 비교 | 생성 장 → 엑셀 → 색인 순으로 다시 만든다 |
| ② 원천 데이터 재생성 비교 | 원천 데이터 생성기를 **쓰기 없이** 돌려 `data/*.gen.json` 과 비교(쓰기를 가로채는 preload 모듈) | 원천 데이터부터 다시 만든다 |
| ③ 추적 끊김 래칫 | 끊김 네 종류의 수가 기준선보다 늘었는가 | 연결을 채운다. 줄었으면 `--update-baseline` |
| ④ 정합 검사 | 아래 목록, 오류 0 | 오류 목록대로 고친다 |

- 빠른 모드(`--fast`)는 ①② 를 건너뛰고, 생성 장은 머리 해시로만 본다.
- 실행 환경에 따라 결과가 달라지는 생성기(예: 시험 결과 폴더 위치에 기대는 것)는 ② 비교에서 뺀다.
- 실패 메시지에 고치는 명령을 함께 적는다.

정합 검사(`check.mjs`)가 잡는 것: 대장 · 권 메타 형식 오류와 번호 중복 · 대장과 다른 분류 · 제목 / 장 파일 없음 · `##` 로 시작하지 않음 · 절 없음 / 근거 경로 없음 / 그림 원본 없음 / 「해요」 · 「합니다」 어미 · 글쓰기 금지 표현 / 출력 자리 · 표지 배포 등급 / 생성물을 손으로 고침 · 오래됨 · 「N개 중 N개 수록」 없음 · 분량 하한 미달 / 색인 드리프트 / 권마다 `syncedCommit` 이후 바뀐 근거 소스(오류가 아니라 현행화 목록).

설명 래칫: 화면 항목 원장처럼 사람이 채울 칸이 있는 원천은 빈 칸 수를 기준선과 비교한다. 기준선에 없는 새 항목의 칸이 비면 실패하고, 빈 칸이 줄면 통과한다(`desc-ratchet.mjs`).
