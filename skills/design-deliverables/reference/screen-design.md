# 화면 설계서 — SI 화면기획서 양식

화면 목록 · 라우트 · 항목을 표로만 실으면, 처음 보는 사람이 메뉴 구조 · 역할별 기능 · 업무 흐름 · 화면 요소의 동작을 한 번에 알기 어렵다. 그래서 국내 SI 화면설계서의 권 구성을 따른다. 화면마다 캡처 위에 번호 표식을 얹고, 오른쪽 설명 표에 항목 · 동작 · 검증 · 권한을 적는다. 표의 값은 코드와 원장에서 생성하고, 사람은 동작 설명과 정책 문장만 쓴다.

## 1. 권 구성

| 장 | 제목 | 쪽 방향 | 주된 원천 | 생성 · 수기 |
|---|---|---|---|---|
| 0 | 표지 · 개정 이력 · 문서 정보 | 세로 | 권 메타 `revisions` | 생성 |
| 1 | IA — 메뉴 구조도와 화면 ID 체계 | 가로 | 화면 ID 대장 · 라우터 · 메뉴 정의 | 생성(영역 설명만 수기) |
| 2 | 사용자와 권한 | 가로 | 권한 매트릭스 원천 · 서버 역할 정의 | 역할 칸 생성, 「권한이 없을 때 화면 처리」 칸 수기 |
| 3 | 업무 프로세스 | 세로(넓으면 가로) | 수기 흐름도 + 화면 ID | 그림 수기, 그림 안 화면 ID 존재 검사는 생성 |
| 4 | 공통 정책 | 세로 | 로딩 상태 정의 · 메시지 코드 · 대용량 한도 · 저장 규칙 | 수기(값은 원천 인용) |
| 5 | 공통 UI 구성요소 | 가로 | 앱 캡처(헤드리스 2x) · 토큰 CSS | 캡처 생성, 설명 수기 |
| 6 | 화면별 스토리보드 | 가로 | 캡처 + 화면 항목 원장 + 소스 | 표 골격 · 표식 위치 생성, 설명 · 동작 수기 |
| 7 | 화면 액션 정의 | 가로 | 원장의 이벤트 · API · 이동 · 메시지 | 생성 후 수기 보완 |
| 8 | 상태 화면 | 가로 | 상태 캡처 + 로딩 상태 정의 | 캡처 생성, 설명 수기 |
| 부록 | 화면 목록 · 라우트 전수 · 항목 전수 · 화면 동작 흐름 | 세로 | 생성 장 | 생성 |

## 2. 장별 양식

**IA(1장)**: 한 쪽에 사이트맵. 맨 위 줄은 주 메뉴 순서, 그 아래 영역별 화면 ID 상자(화면 ID · 화면명 · 경로). 화면 ID 는 `SCR-<영역>-<번호>`. 단계가 있는 창(마법사)이나 탭 화면은 스토리보드 쪽에만 `SCR-WS-09-S1` 처럼 꼬리를 붙이고, 이 꼬리는 대장에 넣지 않는다.

**사용자와 권한(2장)**: 역할 정의 표 + 권한 매트릭스. 사람 호출자(워크스페이스 역할 · 플랫폼 관리자 · 외부 공유 수신자 · 비로그인)만 다루고, 키 호출자는 권한 매트릭스 권을 인용한다. 매트릭스 행은 「메뉴 · 화면 · 기능」 단위, 행마다 대표 API 하나. 역할 칸은 권한 원장 값을 그대로 옮긴다. 마지막 열 「권한이 없을 때 화면 처리」(숨김 · 비활성 + 사유 · 토스트 후 이동, 실제 문구)는 사람이 쓴다. 열이 많으므로 그 쪽만 가로로 싣는다(`pdf-typeset`).

**업무 프로세스(3장)**: 주요 업무(예: 데이터 연결 → 분석 → 대시보드 → 공유)를 흐름도로 그리고 상자마다 화면 ID 를 단다. 생성기는 그림 안 화면 ID 가 대장에 있는지만 검사한다.

**공통 정책(4장)**: 정책마다 「규칙 · 화면 표현 · 근거 소스」 3칸 표. 대상: 입력 검증 · 확인 대화상자 · 목록 · 페이징 · 정렬 · 저장 · 자동 저장 · 나가기 확인 · 대용량 한도 · 세션 · 로그아웃 · 오류 · 빈 화면 · 로딩 표시.

**공통 UI 구성요소(5장)**: 실제 앱에서 잘라 낸 캡처에 번호를 붙이고, 아래에 역할 한 줄과 정본 파일을 적는다. 시험 스택에서 `data-testid` 상자 단위로 자른다. 그래서 화면이 바뀌어도 다시 찍기만 하면 된다.

**화면별 스토리보드(6장)** — 가로 A4 한 쪽:
- 머리 표: 화면 ID · 화면명 · 경로 · 접근 권한 · 진입 경로 · 관련 요구사항 ID, 오른쪽에 문서명 · 버전 · 쪽 번호.
- 왼쪽(약 585px): 1440×900 캡처(2x). 캡처 위에 번호 원과 테두리. 아래에 캡처 조건(계정 · 데이터 · 구성)과 항목별 근거 `파일:줄`.
- 오른쪽 설명 표: 번호 · 항목 · 유형 · 설명 · 동작(클릭 · 입력 시) · 검증 · 메시지 · 권한.
- 한 쪽에 8행까지. 넘으면 같은 캡처를 다시 싣고 (1/2) · (2/2) 로 나누며, 그 쪽의 번호만 진하게 · 나머지는 흐리게.
- 번호 표식 위치는 캡처할 때 `data-testid` 상자 좌표로 함께 저장한다. 그래서 배치가 바뀌어도 표식을 손으로 옮기지 않는다.
- 표식 · 설명이 아직 없으면 그 자리에 `> **예정**:` 으로 채울 시점을 적는다.

**화면 액션 정의(7장)**: 화면마다 이벤트 표. 열은 ID · 트리거 · 처리 · 호출 API · 성공 결과 · 실패 · 예외 결과 · 이동 화면. 트리거 · API · 메시지 · 이동은 원장에서 생성하고 처리 · 결과 문장은 사람이 보완한다. 권한 거부 응답은 권한 원장 칸 값을 쓴다.

**상태 화면(8장)**: 빈 화면 · 불러오는 중 · 찾을 수 없음 · 오류 · 권한 없음 · 좁은 폭(390px)을 공통 쪽 하나로 보이고, 화면별 스토리보드에는 해당 상태만 썸네일로 붙인다. 불러오는 중은 시험 스택에서 API 응답을 늦춰 잡는다.

## 3. 화면 ID 대장과 화면 항목 원장

**화면 ID 대장(`data/screens.json`)** — 한 줄에 `id · name · kind(화면 · 화면 절 · 창 · 패널 · 개발 전용) · route · react · vue(구현 파일) · access · shell · note`. 화면을 없애면 `retired` 표시를 붙이고 행을 지우지 않는다.

**화면 항목 원장(`data/screen-items.json`)과 추출기(`screen_items.py`)**:
- 화면마다 `seed`(시작 파일 · `경로#함수` · `경로:시작줄-끝줄`)에서 출발해, JSX 로 그리는 하위 컴포넌트를 import 로 따라가며 항목을 뽑는다.
- 따라가지 않는 파일: 다른 화면의 seed(화면 경계) · 공통 UI 폴더(5장 담당) · 일정 수(`SHARED_MAX`)보다 많은 화면이 닿는 공용 부품(목록만 `shared` 에). 훑은 파일은 화면의 `scope` 에 적는다.
- **항목 ID 안정 규칙**: 항목 ID = `<화면 ID>-<번호>`. 같은 항목을 찾는 열쇠 `key` = `파일|data-testid` 또는 `파일|종류|라벨`(겹치면 `#2` · `#3`). 줄 번호는 key 에 넣지 않는다. 다시 뽑으면 같은 key 는 예전 ID 와 수기 필드를 이어받고, 새 key 는 화면의 `nextNo` 부터 번호를 받는다. 사라진 번호는 다시 쓰지 않는다.
- **수기 필드**: `desc`(설명) · `action`(동작) · `validation`(검증 · 메시지) · `perm`(권한) · `marker`(캡처 위 번호 좌표). 추출기는 만들지 않고 옮겨 싣기만 한다. 항목이 사라지면 값도 지우고, 지운 목록을 출력한다. 추출로 안 잡히는 항목은 `hand: true` 손 항목으로 넣고 통째로 보존한다.
- 수기 문장은 Markdown 본문이 아니라 원장 필드에 둔다. 그래서 설명 래칫이 「새 항목인데 설명이 빈 것」을 실패로 잡는다.

## 4. 생성 · 수기 경계

| 구분 | 원천 | 갱신 |
|---|---|---|
| 화면 ID · 경로 · 접근 조건 | 대장 · 라우터 | 생성 |
| 항목 목록 · 유형 · 이벤트 · API · 메시지 | 항목 원장(소스 정적 분석) | 생성 |
| 역할별 허용 · 거부 | 권한 원장 | 생성 |
| 캡처 · 번호 표식 좌표 | 시험 스택 캡처 스크립트(헤드리스 2x) | 생성(버전 출하 전 1회 재촬영) |
| 항목 설명 · 동작 · 화면 처리 | 소스 정독 | 수기(원장 필드) |
| 업무 흐름도 · 공통 정책 문장 | 소스 · 명세 | 수기 |

## 5. 현행화 규칙

- 화면 추가 · 삭제 → 대장 행을 먼저 고치고, 같은 변경에서 스토리보드와 IA 를 다시 생성한다.
- 화면 요소 변경 → 항목 원장을 다시 뽑고, 새 항목의 `desc` · `action` 을 같은 변경에서 채운다.
- 경로만 바뀜 → 화면 ID 는 그대로, 대장 `route` 와 옛 주소 보내기 규칙, 생성 장. 구현 파일 이동 → 대장 `react` · `vue`.
- 화면을 둘로 나눔 → 기존 ID 는 큰 쪽에 남기고 새 ID 하나를 더한다. 화면 ID 를 쓰는 다른 권(유즈케이스 · 추적표 · 시험 케이스)의 행도 고친다.
- API 권한 변경 → 권한 매트릭스를 다시 생성하면 2장 역할 칸이 따라온다.
- 캡처는 기능 변경마다 찍지 않고, 버전 출하 전 통합 검증 뒤 한 번 다시 찍는다.

## 6. 캡처 운영

- 격리 시험 스택(시험 전용 DB · 포트)에 시드 계정으로 세션을 심고, 헤드리스 Chrome 2x 로 찍는다. 운영 · 개인 서버 포트는 캡처 스크립트가 거부하게 한다.
- 찍는 동안 만든 시험 데이터는 끝에 지운다. 띄운 브라우저는 그 프로세스가 PID 로 닫는다.
- PNG 는 2x 로 찍고, 조판은 PNG 머리의 크기를 배율로 나눈 CSS 픽셀로 싣는다(`pdf-typeset` 4절 · 기준 저장소의 `png-size.mjs`).
