# 디자인 시스템 견본 그림 — 실제 CSS 로 렌더해 2x 로 굽기

디자인 시스템 가이드와 UI 가이드가 토큰 · 클래스를 표로만 정의하면, 실제 모양을 보려고 앱을 띄워야 한다. 그래서 저장소의 토큰 CSS 를 그대로 읽어 견본 HTML 을 만들고 헤드리스 Chrome 2x 로 절마다 PNG 를 찍는다. 그림을 손으로 그리거나 흉내 내지 않는다.

## 1. 구성(기준 저장소의 `scripts/deliverables/ds-specimen/`)

| 파일 | 하는 일 |
|---|---|
| `extract.mjs` | 토큰 CSS 에서 CSS 변수와 공용 클래스를 **줄 번호와 함께** 읽는다. 셈 규칙은 문서의 토큰 · 클래스 생성 장과 같게 둔다(주석을 빼고 이름을 센다) |
| `specimen.mjs` | 절(그림 한 장) 목록과 HTML 을 만든다 |
| `build.mjs` | HTML 을 만들고 헤드리스 Chrome 2x 로 절마다 PNG(밝은 · 어두운)를 찍는다 |
| `ui-plan.mjs` | 도메인 컴포넌트 캡처 계획(계획 한 줄 = 그림 한 장) |
| `capture-ui.mjs` | 계획대로 시험 스택 화면을 2x 로 찍는다(`--plan` 은 앱 없이 계획만 출력) |
| `specimen.test.mjs` | 견본 단위 시험 |

## 2. 절 구성

- **토큰 절**: 읽은 토큰 전부를 종류(색 · 글자 · 간격 · 모서리 · 그림자 · 층위 · 그 밖)별로 싣는다. 색은 이름 묶음 단위로 나눠 그림 여러 장(`tok-color-1`, `-2` …)으로 싣는다.
- **프리미티브 절**: 버튼 변형 · 배지 · 안내 · 토스트 색 계열은 CSS 에 정의된 클래스에서 고른다. 입력 · 선택 · 창은 견본 마크업을 쓴다.
- **계열 지도 절**: 공용 클래스 전부를 계열별로 세고, 견본에 실린 클래스 수를 함께 적는다.
- **도메인 컴포넌트**: 앱 화면에서 프리미티브를 조합한 부품(트리 행 · 토스트 등)을 잘라 낸다.
- 그림 아래에 정본 위치(`<토큰 파일>:<줄>`)를 찍는다. 줄 번호는 생성할 때 CSS 에서 찾는다.
- 그래서 토큰 · 클래스를 새로 만들면 다음 생성 때 그림에 그대로 나온다.

## 3. 상태 고정 · 캡처 계획 키

- hover · focus 는 CDP `CSS.forcePseudoState` 로 고정한다. 포커스 링이 특정 속성(예: `<html data-a11y="on">`)에서만 그려지면 그 상태로 찍는다.
- 캡처 계획 한 줄의 키:
  - `screen`: 어느 화면을 어떤 역할로 여는지(준비 함수 키)
  - `action`: 찍기 전 조작(조작 함수 키, 없으면 그대로)
  - `target`: 잘라 낼 요소 — `testid`(첫 요소) · `css`(마지막 요소) · `topStrip`(화면 위 띠)
  - `crop`: `pad` 또는 방향별 여백, `maxH`(높이 상한), `split`(가로 n 등분 — 화면 폭 띠를 본문 폭에 줄이면 글자가 너무 작아져서 나눠 싣는다)
  - `fig`: 원고의 그림 줄 번호 · 들어갈 절. `addAfterCapture` 는 캡처 뒤에 그림 줄을 넣는다는 뜻
- 좌표는 CSS px(뷰포트 1440 × 900), 2x 로 찍는다.

## 4. 커밋 경계

- 토큰 견본 그림(`figures/ds-*.png`)은 다시 만드는 생성물이라 커밋하지 않는다. 그래서 그 권을 조판하기 전에 견본 생성 명령을 먼저 돌린다.
- 앱 캡처(`figures/ui-*.png`)는 시험 스택이 있어야 다시 찍을 수 있으므로 커밋한다.
- 두 그림 모두 디자인 시스템 토큰과 공용 클래스로만 그린다. 로컬로 다시 꾸민 견본은 실제 화면과 모양이 달라 판단 근거가 되지 않는다.
- 무거운 작업이 돌 때는 `uptime` 1분 평균 20 아래에서 돌리고, 띄운 브라우저는 그 프로세스가 닫는다(패턴 종료 금지).
