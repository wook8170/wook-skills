# 용어 사전 · 용어 검사 (범용판)

## 1. 왜 필요한가

용어 결정은 대화 · 지시서 · 메모 · 명세 표 · 시험 코드의 금지어 목록에 따로 적히기 쉽다. 결정을 뒤집으면 일부만 고쳐지고,
철회된 결정이 지시서에 남아 다른 작업에서 다시 적용된다(한 BI 제품 저장소의 2026-10-15 사례: 「적재 → 추출」 철회가 지시서에 남음). 사전을 하나 두고
나머지는 사전에서 만들거나 사전을 읽게 하면, 결정을 한 곳에서 바꾸고 검사가 나머지를 따라오게 할 수 있다.

## 2. 까는 순서

1. **파일 배치** — 이 스킬의 `templates/` 를 프로젝트에 복사한다.
   ```
   templates/terms.yaml  → docs/glossary/terms.yaml     정본 사전(스키마 주석 포함)
   templates/config.json → docs/glossary/config.json    검사 범위 · 짝 · 무시 목록
   templates/lib.mjs     → scripts/glossary/lib.mjs     파서 · 추출 · 판정(의존 0)
   templates/check.mjs   → scripts/glossary/check.mjs   게이트
   ```
   `lib.mjs` 는 저장소 루트를 `scripts/glossary/` 기준 두 단계 위로 잡는다. 다른 곳에 두면 `REPO` 를 고친다.
2. **초기 항목 채우기** — 흩어진 출처를 모두 모은다: 문구 명세 · 기존 금지어 목록(시험 코드) · 지시서 · 메모 · 최근 결정 기록 ·
   매뉴얼 용어집. 겹치거나 모순되면 **가장 최근 결정**을 따르고, 철회된 결정은 `decided` 에 「(이전 결정) 철회」로 남긴다.
   모순 정리표(주제 · A 출처 · B 출처 · 채택)를 보고서에 낸다.
3. **범위 정하기** — `config.json` 의 `sources` 에 화면 소스 · 매뉴얼 · 서버 오류 문구 · 도구 설명 · 고객 문서를 카테고리와 함께 적는다.
   매뉴얼처럼 좁은 범위를 넓은 범위(ui)보다 **먼저** 적는다(앞 규칙이 이긴다). 규칙 문서 자신(금지어를 나열하는 명세)과 생성물은 `exclude`.
   React↔Vue 같은 두 벌 앱이면 `pairs` 에 두 소스 루트를 적는다.
4. **첫 실행 · 기준선** — 기존 위반은 고치지 않고 잠근다.
   ```bash
   node scripts/glossary/check.mjs --json /tmp/glossary.json   # 오탐 확인용 전체 결과
   node scripts/glossary/check.mjs --update-baseline            # docs/glossary/baseline.json · unregistered-baseline.json
   node scripts/glossary/check.mjs --top 30                     # 미등록 상위 30 → 결정자에게 「등록 / 다른 말로 / 무시」 질문
   ```
5. **게이트 편입** — `package.json` 에 `glossary:check`(검사 + 단위 시험) · `glossary:baseline` · `glossary:top` 을 만들고 게이트 체인에 넣는다.
6. **기존 하드코딩 제거** — 시험 코드의 금지어 배열 · 명세의 용어 표 · 화면 스캔 규칙은 사전에서 만들거나(생성 + `--check` 드리프트 검사)
   사전을 읽게 바꾼다. 생성기는 `scripts/glossary/gen.mjs` 같은 한 파일로 둔다(용어집 README · 매뉴얼 데이터 · 명세 표 · 화면 스캔 규칙).

## 3. 오탐 줄이기 — 처음 실행 뒤 반드시 훑는다

`--json` 결과를 항목별로 3~4건씩 실제 줄과 함께 읽는다. 한 BI 제품 저장소의 첫 실행에서 실제로 나온 오탐과 처방:

| 오탐 | 처방 |
|---|---|
| 낱말 안의 글자(「직전 단계보다」의 「계보」, 「비활성 판정」의 「활성 판」) | `re:(?<![가-힣])계보(?!다)` 처럼 앞뒤 경계를 둔 정규식 |
| 복합어 · 다른 뜻(미리보기 · 오른쪽 · 스타일 추출) | 항목 `exceptions`(먼저 가린 뒤 찾는다) |
| Vue 파일 머리의 `<!-- -->` 주석, 주석 안의 「<style>」 글자 | 블록을 줄 첫 칸에서만 인식(lib 에 반영됨) |
| 검색 동의어 배열(옛 이름으로도 찾게 둔 `keywords: [...]`) | `config.blankPatterns` |
| 서버 로그 · 감사 기록 값 | `config.skipLinePatterns[category]` |
| 미등록 후보의 일반 낱말(취소 · 저장 · 이름) | `config.ignore` |

## 4. 판정 규칙 요약

- **금지어**: 파일 × 항목별 건수가 기준선보다 늘면 실패. 줄면 통과하고 다시 잠그라고 안내한다. `status: 검토` 는 경고만.
- **R↔V 불일치**: 같은 상대 경로(확장자 무시)의 두 파일이 한 항목에서 금지어 건수가 다르면 불일치. 기준선에 없는 새 불일치는 실패.
- **미등록 래칫**: 버튼 · 제목(h1~h6) · 표 머리 · 옵션 · 탭 · 배지 · `label`/`title`/`aria-label` 문자열에서 한글 낱말을 뽑아
  조사를 떼고 동사형을 버린 뒤, 사전 쓰는 말 · 별칭 · ignore 에 없는 것을 센다. 기준선에 없는 새 낱말이 생기면 실패.
- **동의어 충돌**: 새 낱말이 어떤 항목의 쓰지 않는 말과 같으면 실패, 쓰는 말과 한 글자 차이면 경고. 사전 안에서 한 항목의
  쓰는 말이 다른 항목의 쓰지 않는 말이면 형식 오류로 실패.

## 5. 문구를 쓸 때의 절차(설치 뒤)

사전 확인 → 없으면 `status: 검토` 로 등록 제안 → 결정이 필요한 것은 「등록 / 다른 말로 / 무시」 선택지 표로 모아 한 번에 묻는다 →
`glossary:check`. 기준선은 늘리지 않는다(늘려야 하면 결정자 확인 뒤, 보고서에 적는다).

## 6. 함정

- 한글 소스를 `grep` 하면 바이너리로 오인해 빈 결과가 나온다 → `LC_ALL=C grep -a`. 검사 스크립트는 Node 로 읽어 영향이 없다.
- 사전 파서는 부분 집합만 읽는다(블록 리스트 · 줄 전체 주석). `[a, b]` 흐름 표기는 조용히 틀리게 읽지 않고 예외를 낸다.
- 시험 러너(vitest 등)에서 검사 함수를 재사용하려면 **저장소 절대 경로**로 동적 import 한다
  (`import(/* @vite-ignore */ `${repoRoot}/scripts/glossary/check.mjs`)`). 앱 루트 밖 상대 경로는 Vite 가 «앱 루트 기준 /scripts» 로 풀어
  못 찾고, jsdom 환경의 `import.meta.url` 은 http: 라 `new URL(…, import.meta.url)` 도 실패한다. repoRoot 는 시험 작업 디렉터리
  (`process.cwd()`)에서 앱 경로를 떼어 만든다.
